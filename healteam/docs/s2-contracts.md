# S2 本地运行与恢复约定

版本 0.3.0，数据库继续使用 schema v1。S2 在 [S1 接口](s1-contracts.md) 的人工训练闭环上增加故障保护，不接入真实模型、专业评分或多用户服务。

## 进程所有权

应用在初始化数据库及恢复会话之前，必须取得规范数据库路径对应的 `RuntimeLease`。锁文件名为数据库文件名追加 `.lock`，Windows 使用字节范围锁，POSIX 使用 flock。锁由操作系统持有，不使用过期时间抢占；暂停进程或生成缓慢不会让另一个实例夺取所有权。进程退出或崩溃后内核释放锁，文件本身不删除。

同进程重复应用对象也要争用锁。未取得锁的实例保留 `/healthz`，但 `/readyz` 和业务接口返回 503 / `runtime_in_use`，不会执行恢复或修改首实例的记录。前端以 `/readyz` 判断是否可以开始练习。

停机顺序为停止接受新命令、撤销旧任务写入资格、等待任务、保存中断状态、释放仓储，最后释放进程锁。仓储在取得 SQLite 写锁后、执行变更回调前和提交前检查本地 `write_guard`，失权返回 `runtime_not_owned`；等待写锁的旧请求不能在新实例启动后补写。

运行管理器还核对命令生命周期。停机前进入、停机后才恢复的输入/创建请求，不能激活旧任务；同一个管理器对象重新启动也不会接纳上一代请求。

## 时间预算

| 配置 | 默认秒数 | 范围 | 作用 |
|---|---:|---|---|
| HEALTEAM_OPERATION_TIMEOUT_SECONDS | 60 | 大于 0，最多 600 | 每次家庭回应、监督步骤、报告生成 |
| HEALTEAM_STOP_TIMEOUT_SECONDS | 2 | 大于 0，最多 10 | 等待已撤销任务停止 |
| HEALTEAM_STORAGE_BUSY_TIMEOUT_SECONDS | 2 | 大于 0，最多 30 | 每次 SQLite 写锁等待 |

这些是各步骤的独立预算，不是整场训练或整个 HTTP 请求的总时限。SQLite 按毫秒归一预算；争用超时不自动重跑变更回调。API 返回安全的 `storage_unavailable`，释放锁后可按原幂等 ID 重试。

生成超时保存 `response_timeout` 或 `report_timeout`。对话中断不计作完整回合，已接受的人类输入保留。生成调用与持久化分离；取消或超时后返回的旧结果被丢弃，旧 worker 不能覆盖取消、重试成功或新实例的数据。

取消等待有界并不等于强行终止任意 Python 代码。拒绝取消的异步生成可能继续运行至返回，但结果不再写入；同步死循环阻塞整个事件循环仍需结束进程。数据库操作另有写锁预算。

## 重启与复盘重试

| 保存状态 | 重启后的行为 |
|---|---|
| awaiting_input | 保持等待，可继续输入 |
| simulation 中的 created/running/cancelling | 保存为 interrupted；已有半轮只读，不补发回应 |
| supervision/report 中断且未取消 | interrupted + report_state=failed，可单独重试复盘 |
| 用户已取消的复盘 | 保留取消结果，不提供重试 |
| completed/cancelled | 保持已提交结果 |

`POST /api/v1/reports/{id}/retry` 现在允许 state 为 failed 或 interrupted、phase 为 supervision/report 且报告失败的会话。重试仍在原阶段开始，清除旧错误；不能增加已完成轮次或追加治疗室发言。若另有活跃会话，返回 409 及该会话 ID，不能抢占。

报告、终态和事件继续原子提交。completed/cancelled 仍不可更改；interrupted 只为上述失败复盘开放受限的 running 转移。对话中断不开放同会话续跑。

## 浏览器恢复

普通 API 请求最多等待 15 秒。发送超时只表示浏览器未确认结果，不推断后端没有接受请求，也不自动重发。

当前标签页的 sessionStorage 保存未发送草稿，以及待确认请求的原 client_message_id、expected_turn 和 content。刷新后先按保存事件中的 client_message_id 精确核对；未确认时禁止编辑新的干预，提供核对和重放同一请求的操作。确认成功或会话终结后清理。关闭标签页会失去该标签页草稿；浏览器禁用存储时仅保留内存恢复能力。

SSE 仍按持久 seq 重连，断线期间每 3 秒补读快照并提示连接状态。断线不会重启 worker 或自动重发输入。旧快照/报告查询按世代过滤；迟到的提交响应只能清理匹配请求 ID 的草稿，不能覆盖新内容。

## 交付与适用范围

默认仍为本机单人、单进程、一个活跃会话。S2 没有引入外部任务队列或数据库。静态病例和流派文件属于运行资源，必须随源码交付；SQLite、锁文件、密钥与训练输出不进入源码包。`scripts/package_source.py --verify-run` 会验证资源清单并解压运行离线冒烟。

本阶段验证了确定的崩溃、争用、网络和迟到响应情形，以及 30 轮重复请求检验；不等同于长期生产压力或所有平台故障均已覆盖。容器运行、真实模型和专业教学有效性仍待后续阶段验收。
