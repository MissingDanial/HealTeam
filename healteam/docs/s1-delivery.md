# S1 交付与验收记录

验收日期：2026-11-04（Asia/Shanghai）  
版本：0.2.0  
目标：完成单人、本地、离线训练的完整闭环。

## 已交付行为

1. 首页选择拒学病例、三个流派之一、轮数与参与方式。亲自练习默认由学员担任治疗师，自动示范单独标识。
2. 新建会话获得稳定地址。学员提交干预后，系统生成一至三个家庭成员的确定性模板回应，完成后允许继续输入。人工训练不生成 AI 医生发言。
3. 至少完成一轮后可主动结束；达到轮数上限也会进入复盘。流程报告保存实际对话的事件引用，不提供专业评分。
4. 会话、对话事件、幂等收据与报告保存在本机 SQLite。首页历史支持分页，刷新或重新启动应用后可重新打开报告。
5. 等待输入的会话在重启后可继续。正在生成时停机的会话标记为中断，不自动重复半轮。取消保留已提交内容；失败的复盘可以单独重试。
6. 浏览器使用原生事件订阅，连接与执行相互独立。断线按事件序号重放，刷新不会另启动一次生成。

所有回应和报告明确标识为 mock 固定模板。流派选择会被保存，但本阶段没有实现真实流派推理、专业督导或治疗效果判断。全程未调用外部模型。

## 验收中修复的问题

- 前端代理压缩缓冲了事件流，导致后端完成而页面仍等待。SSE 现使用 `Cache-Control: no-cache, no-transform`，实测直连和代理均能及时收到事件。
- 旧一轮已经保存等待状态、执行任务尚未退出时，新输入可能无人接手。现在按会话串行交接已接受操作，并有窗口回归测试。
- 报告生成中停机可能永久显示生成中。重启恢复会保存中断和报告失败状态。
- 创建重放曾依赖当前病例资源重新通过验证。现在先查持久收据，已成功请求不因资源后续失效而失去幂等性。
- 历史示范接口可绕过单活跃会话约束。标准应用现返回 410，示范统一进入正式持久接口。
- 未知数据库版本启动失败后可能触发无效清理。现在只关闭成功启动的管理器，并始终释放仓储。

## 验收边界

- 仅支持本机单进程执行与一个活跃会话；没有多用户登录或多进程任务调度。
- 已验证基本取消、幂等、事件重放和停机标记，尚未完成后续阶段的长期压力、故障注入和自动恢复验收。
- 未接入真实模型或外部服务，未验证专业教学有效性。
- Docker 配置已同步持久卷，但容器构建与运行未实测。
- S0 文件报告不会自动导入 S1 数据库。
